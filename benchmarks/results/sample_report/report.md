## 1. Scope and setup

**Question.** On one benchmark circuit, under the same input domain, threshold, CKKS parameters and key set, do FHEOracle (default settings) and AutoOracle (the recommended entry point) report a larger worst-case output error than uniform random sampling or a corner/boundary test set? FHEOracle is compared at equal evaluation budget and at equal wall-clock budget; AutoOracle at equal evaluation budget and against FHEOracle.

**Circuit** (`benchmarks/tenseal_circuits.py::build_tenseal_lr_d8`).

- Intended model: σ(z) = 1 / (1 + e^(−z)), z = w·x + b, evaluated in float64 plaintext.
- Polynomial surrogate: T3(z) = 0.5 + z/4 − z³/48 (Taylor-3 sigmoid).
- FHE program: x encrypted as a CKKS vector; z = ⟨ct_x, w⟩ + b; T3(z) evaluated homomorphically; slot 0 decrypted.
- Weights: 200 steps of gradient descent on synthetic data (seed 42). w = `[-0.1172, 1.2576, 1.3732, -1.3651, -0.2172, 1.2282, 0.3565, 0.4254]`, b = -0.080384.
- Input domain (all methods): [-3.0, 3.0]^8. Every evaluated input was checked to lie inside it.
- Threshold (all methods): 0.01 absolute error on the probability output.

## 2. Method

**FHEOracle.** `FHEOracle(plaintext_fn, fhe_fn, input_dim=8, input_bounds, seed=s).run(n_trials=200, threshold=0.01)` with library defaults (CMA-ES, σ0 = 1.0, start at the box centre, pure divergence fitness, no random floor, no restarts, no heuristic seeds, no plugins). `run()` evaluates at most `n_trials` search points (a partial final CMA-ES generation is evaluated but not told to CMA-ES), then re-measures its reported witness once. This is the configuration behind the README `lr_matched` row; it was not tuned for this report.

**AutoOracle.** `AutoOracle(plaintext_fn, fhe_fn, bounds).run(n_trials=200, threshold=0.01, seed=s)` with library defaults (configured `n_probes` = 50; no `W, b`, so the preactivation test is off). It probes the landscape, classifies a regime and dispatches to an inner `FHEOracle` configuration. The exact probe steps are those of `fhe_oracle/autoconfig.py` with the SHA-256 recorded in section 1. Strategies used in this run:

- `cma_es`: default CMA-ES, the same settings as the FHEOracle column.
- `robust_cma_es`: CMA-ES with σ0 = mean box width / 4 and 10 injected heuristic seeds; with no heuristic plugin registered these come from Core's `fallback_corner_seeds` (5 random box vertices and 5 uniform points).

**Uniform random.** Independent uniform draws from the same box (NumPy `default_rng(s)`).

**Corner/boundary set.** A fixed pool of 273 points: all 2^8 vertices, the 16 face centres and the box centre. Each seed evaluates the pool in a seeded random order until its budget is spent; the pool is not re-used.

**Counting.** Every call to the plaintext model and to the CKKS program is counted for every method, including every AutoOracle evaluation and FHEOracle's re-measurement of its reported witness. For logging, the plaintext model and surrogate are recomputed at each FHE call; that instrumentation is identical for all methods and is not counted as search effort. Both tools' `on_evaluation` events are written to JSON Lines logs (`evaluation_logs/`, one per tool per seed, via `fhe_oracle.evallog.JsonlEvaluationLog`) and matched one-to-one, in order, against the counted FHE calls; their SHA-256 digests are listed in the appendix.

**Equal evaluation budget.** Each baseline is cut from one seeded stream per seed at exactly FHEOracle's counted FHE evaluations, and again at AutoOracle's.

**Equal wall-clock budget (FHEOracle only).** Each baseline receives FHEOracle's measured wall time for that seed (construction plus `run()`), and counts only evaluations that completed within it, cut from the same seeded stream.

**AutoOracle vs FHEOracle.** Paired by seed at the same `n_trials`; the two tools' counted evaluations differ as reported above.

**Statistics.** Per-seed max-error ratio (tool / reference), counts of seeds where the tool's value is larger, smaller or tied, and a paired two-sided Wilcoxon signed-rank test (scipy, `zero_method='wilcox'`) on the per-seed differences. A difference with absolute value at most TIE_TOL = 1e-05 is a tie: it is set to zero, so the test drops it, and it is counted in the tie column. 7 tests are reported; Holm adjustment is applied across all of them. Seeds vary the search randomness only; the circuit and keys are fixed.

**Why TIE_TOL.** CKKS adds fresh noise to every encryption, so the same input measures slightly differently each time, and a maximum over evaluations gives a method that re-measures its witness an extra noise draw. The largest spread between repeated measurements of the same input in this run is 1.70e-06, so TIE_TOL is about 6 times that spread. The value is the margin that `benchmarks/preregistration_2026-09-15.md` uses for comparisons against the corner set. This tolerance was adopted after the first 20-seed run of this report showed noise-level differences counted as wins for AutoOracle over the corner set.

## 5. What PASS and FAIL mean

- **FAIL** means the tool evaluated a specific input, inside the stated domain, whose output differed from the intended model by at least the threshold (0.01); in this library version any counted search evaluation can set it. The final re-measurement at FHEOracle's reported witness also met the threshold on 20/20 FHEOracle FAIL seeds. Re-running the model on FHEOracle's reported witness met the threshold on 5/5 fresh encryptions here. A witness whose error sits within CKKS noise of the threshold can re-evaluate below it (see the shrunk witness in section 4).
- **PASS** means no threshold violation was observed during the specified search, on the stated domain, budget, parameters and backend version. It is not proof of correctness, cryptographic security or regulatory compliance, and says nothing about inputs outside the domain.
- A method that reports a larger maximum error has found a worse input; it has not necessarily found more distinct defects.

## 6. Limitations

- **One circuit.** A d = 8 logistic regression with synthetic weights. It is a benchmark circuit, not a customer model; results depend on circuit, domain, parameters and search strategy.
- **Mostly approximation error.** The comparisons above measure how well each method locates a surrogate-design defect that is visible without encryption. A search targeting CKKS execution error alone was not run.
- **Worst case at a vertex.** For this circuit the error grows with |w·x + b|, so the maximum sits at a box vertex, which favours a corner/boundary test set and any method that evaluates box vertices (for example injected corner seeds or a boundary probe). Circuits with interior worst cases may rank the methods differently.
- **One budget and two configurations.** `n_trials` = 200; FHEOracle and AutoOracle with library defaults. `check()`, explicit restarts and random-floor options were not evaluated separately. The README's historical `lr_matched` row uses B = 60, does not count the oracle's re-measurement and has no wall-clock comparison, so it is not directly comparable.
- **Timing.** One machine, sequential runs in one process (FHEOracle, then AutoOracle, then the baseline streams, for each seed), no isolation from other system load. Equal-time evaluation counts will differ on other hardware.
- **Not bit-reproducible.** CKKS encryption randomness is not seeded (the `TenSEALContext` seed argument is unused), so reruns differ in low-order digits and searches can follow different paths.
- **Not independently replicated.** Produced by the tool's author's own script.
- **No operational-profile replay.** Inputs from a real deployment distribution were not tested; the uniform box is an adversarial domain, not a usage profile.
- **Statistics.** 20 paired seeds on one fixed circuit; p-values describe search randomness, not variation across models.
- **Tie tolerance chosen after the first run.** TIE_TOL was adopted after the first 20-seed run of this report counted CKKS-noise-level differences as wins. With it, AutoOracle and the corner set match within noise on 13/20 seeds. The corner set's evaluation budget did not reach the worst vertex on 7/20 seeds, and those are the only seeds where AutoOracle is larger (7/20).
